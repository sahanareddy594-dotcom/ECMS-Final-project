# AXILEX ECMS — Deployment Guide

This Flask app is hosting-ready for **Render**, **Railway**, **PythonAnywhere**,
and any platform that runs Python 3.11+ with `gunicorn`.

## 1. Render (recommended)
1. Push this folder to a GitHub repo.
2. On https://render.com → **New → Blueprint**, point to the repo
   (the included `render.yaml` will be detected).
3. Add environment variables in the dashboard:
   - `SECRET_KEY` — auto-generated by render.yaml
   - `RAZORPAY_KEY_ID` / `RAZORPAY_KEY_SECRET` (test keys)
   - `DATABASE_URL` (optional, see Postgres section)
4. Click **Apply** — Render builds and serves at `https://<name>.onrender.com`.

## 2. Railway
1. `railway init` → `railway up` from this folder.
2. Add the same env vars in the Railway dashboard.
3. Railway auto-detects `Procfile` and runs `gunicorn app:app`.

## 3. PythonAnywhere
1. Upload the folder, create a new Web app (Manual config, Python 3.11).
2. Virtualenv: `pip install -r requirements.txt`
3. WSGI file:
   ```python
   import sys
   path = '/home/<USER>/week_5_task'
   if path not in sys.path: sys.path.insert(0, path)
   from app import app as application
   ```
4. Add env vars in the **Web → Environment variables** section.

## 4. Razorpay (Test Mode)
1. Sign up at https://dashboard.razorpay.com → enable **Test Mode**.
2. Settings → API Keys → **Generate Test Key**.
3. Add `RAZORPAY_KEY_ID` and `RAZORPAY_KEY_SECRET` as env vars.
4. Use Razorpay test cards: `4111 1111 1111 1111`, any CVV / future expiry.
5. UPI test ID: `success@razorpay` for success, `failure@razorpay` for failure.
6. If keys are not set, the app falls back to the built-in mock UPI gateway.

## 5. Cloud database (optional)
Default storage is SQLite (`database.db`) — fine for demos but resets on
ephemeral hosts. For production:

### Supabase / Render Postgres / Railway Postgres
1. Create a Postgres instance and copy the connection string.
2. Set `DATABASE_URL=postgresql://user:pass@host:5432/dbname`.
3. Run the migration once: `python migrate_to_postgres.py`
   (creates the same tables in Postgres and copies SQLite data over).
4. Update `app.py` to use `psycopg2`/SQLAlchemy as needed (the migration
   script ships an example connection helper).

> The default app uses SQLite for zero-setup demos. The `DATABASE_URL`
> env var is read but only used by the migration helper — switch the
> runtime by following the comments inside `migrate_to_postgres.py`.

## 6. Test the deployment
- `GET /healthz` → `{"status":"ok","razorpay":true|false}`
- Default users: `admin/admin123`, `elec/123`, `client/123`
- Run automated tests: `pytest -q`
